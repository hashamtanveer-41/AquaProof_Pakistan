# AquaProof project memory

## Architecture and decisions

- `backend/app/main.py` registers the officer API and background jobs. `database.py` runs transactional SQL migrations under a database lock. Migration 009 retains existing records and adds optional farmer district and tehsil.
- `registry.py` owns the authoritative PostGIS polygon, representative point and stored field history. The map uses Terra Draw for drafts, incremental MapLibre feature updates and geodesic area from PostGIS when saved. Browser drafts estimate area with Turf. EPSG:4326 coordinates use longitude, latitude except human-entered search pairs.
- `arcgis.py` uses private geocoding credentials, checks Pakistani candidates and leaves coordinate navigation available. MapLibre renders ArcGIS v2 styles. The optional server relay serves only known ArcGIS raster and vector services and removes private credentials from the style before sending it to the browser. Alternatively, browser map config can return a separately provisioned public basemap token. MapLibre preserves the closed draft across style replacement.
- FarmMap defaults to Open street and keeps drawing and editing on street. ArcGIS Satellite and Hybrid remain selectable for viewing. A draft preserves the previous basemap preference, viewport, and polygon while the street style loads.
- The React workspace uses registry-backed records and provider-backed data. The stylesheet imports Tailwind Preflight directly for the base reset. Imagery configuration lives in the ArcGIS runtime settings.
- `science/routes.py` exposes farm weather, crop lifecycle, simulation and revision-checked decisions. The FAO-56 soil-water parameters (TAW, initial depletion, allowable depletion, efficiency, surface TEW/REW) are derived from the registered crop and soil type by `irrigation.soil_water_defaults`; the default initial depletion sits at the readily-available-water trigger so the plan yields a net irrigation requirement. The irrigation-settings endpoint accepts only the water supply (canal turn or tubewell) plus optional advanced overrides and stores the composed full settings; `water-plan` and `simulate` fall back to the derived defaults when no record exists, so only the crop calendar and a physical supply are still required. `science/CLAUDE.md` records model rules and attribution.
- `science/openweather.py` normalizes current readings and three-hour forecasts. The irrigation engine receives a separate Open-Meteo forecast with complete Pakistan-local-day rain and reference ET. Never use partial OpenWeather date group totals as irrigation inputs.
- `assistant_model.py` classifies the intent (agentic tool loop) and composes every farmer answer with `compose_answer`, which the model grounds strictly in the facts it is given — it never invents a number and says a figure is unavailable instead of guessing. `assistant_jobs.full_context` assembles one comprehensive fact bundle per answer — stored records, land/area, fresh API weather, live solar and soil-moisture readings, the FAO-56 simulation, the crop-stage timeline (`season_progress`), warabandi schedule, harvest timing and recent history — so the model always has the field's full context. Once a field is identified, `compute` always answers from `full_context` regardless of the classified intent (including `clarify`), so a vague "farm stats/info" question is answered from data, not deflected; only a genuinely unidentifiable field asks which field (or, if none is linked, to have the officer add one). No stored template is used for an answer: if the model is unavailable the worker raises and the job retries. Identity/greeting questions answer as the AquaProof AI assistant; missing inputs are explained in plain language while everything else the facts cover is still answered. Only operational confirmations stay fixed (verification prompt, "verified", observation receipt, officer-review/escalation). `assistant_access.py` applies verified farmer scope and the PostgreSQL reader role. `assistant_jobs.py` queues daily and correction work in PKT and deduplicates by field/day/slot. `assistant_copy.py` holds the fixed operational strings and `answer_facts`/`numbers_line` (the deterministic fallback line). `assistant_whatsapp.py` sends queued direct text via WAHA and accepts signed `message` callbacks at `/webhooks/waha`. `waha.py` validates the session, direct sender identity and provider response, and `serialized_id` normalizes the WEBJS engine's object message `id` (`{_serialized, id, ...}`) for both send and inbound; in Docker the API reaches WAHA at `http://waha:3000`, not `127.0.0.1`. Linked IDs resolve through WAHA and still go through current registry ownership and verification checks. The Settings page pairs and unlinks the sending phone through the officer API. Migration 013 preserves provider history and indexes the officer conversation endpoint.
- Migration 012 defaults new WhatsApp enrollments to Urdu. The farmer's saved preference controls the composed reply language. Automated field answers share one refreshed weather context per field per job. Numbers come from the deterministic engine and the model only phrases and explains them; keep source and outage details in officer evidence. Hazard, salinity, rice and crop-stress cases still route to officer review.
- Legacy email records are retained for field history. Migrations 010 and 011 distinguish transport queues and revoke a farmer's WhatsApp verification and reply tokens when their registered number changes. The prior `/intelligence` contract explains scientific results deterministically.
- `officer_auth.py` verifies the officer password and issues an HTTP-only, same-site browser session for 14 days. API writes enforce the original site origin. Configure an independent signing secret and use secure cookies behind HTTPS.
- Archive retains field history. Explicit permanent deletion locks the field, removes dependent records and message-linked audit rows in one transaction, and evicts its weather point after commit. Keep the farmer identity and sibling fields. API access logs omit request paths and query strings.
- The assistant answers for the authorized field linked to the conversation. `full_context` gathers that field's complete state and the model composes the reply from it for any identified field; only an unidentifiable field (none linked, or several with no match) asks which field or to have the officer add one, and identity/greeting questions answer as the AquaProof AI assistant. When the model's intent classifier falls back to local rules it only chooses the intent and farm — the reply is still model-composed.
- `service_health.py` tests actual upstream responses using public samples and synthetic model requests. The WAHA check is self-healing: it treats the brief `STARTING` reconnection window as healthy, restarts a `STOPPED`/`FAILED` session (the pairing persists in the volume, so no re-scan), retries a transient connection miss, and a dedicated job re-probes it every few minutes so a working session never sits on a stale `degraded`. Only an unpaired `SCAN_QR_CODE` or unreachable session is unhealthy. A `WORKING` session does not by itself establish incoming webhook delivery. `service_http.py` retries transient transport and HTTP failures and opens a short process-local circuit. Admin status retains the endpoint, recent check time, observed latency and available coverage and quota details.

## Security and configuration

Use a dedicated officer secret and distinct WhatsApp reply secret. Enforce TLS at the deployment perimeter. The assistant calls Groq's OpenAI-compatible chat completions endpoint (`assistant_model.config`/`request_model`, `GROQ_API_KEY`/`GROQ_MODEL`, default `openai/gpt-oss-120b`); unlike the prior OpenRouter route this endpoint carries no provider allowlist, data-collection-deny or ZDR routing block, so confirm the Groq account's data-retention terms and obtain deployment approval before it processes farmer data. Keep farmer names and contact details out of model context where practicable. Share exact geometry only by explicit deployment policy. Keep ArcGIS browser and server credentials separate.

The government gateway, named officer identities, deployment authorization and retention policy are separate release inputs. Single-process service health and scheduling are deployment constraints until moved to shared infrastructure.

## Conventions and tests

Use explicit units in public JSON keys, PKT for agricultural dates, UTC for instants, and public provider names in status. Keep calculations deterministic. Farmer replies are composed by the language model but must stay grounded in the engine's deterministic numbers — the model phrases and explains, it does not compute. Unit tests assert the model path, identity answer and model-unavailable retry; the live integration test mocks `compose_answer` to check the composed reply and field isolation and needs a PostGIS database plus Groq to run. Test stale and invalid data, no-rain sensitivity, observed data isolation and retry failure recovery. The setup, contracts and commands are in [README.md](README.md). The verified outcomes and gaps are in [TEST_REPORT.md](TEST_REPORT.md) and [API_STATUS.md](API_STATUS.md).
